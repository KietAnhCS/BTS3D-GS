\section*{B. RESEARCH DESCRIPTION}

\subsection*{B1. Introduction}

This is a course project. Its goal is to study how the original (vanilla) 3D Gaussian Splatting
(3DGS) pipeline works, use it to reconstruct a real Base Transceiver Station (BTS) telecom tower
as a digital twin from drone photographs, and look for a rendering method that works better than
vanilla 3DGS for this kind of scene. A BTS scene is mostly flat surfaces (roofs, walls, sky), but
the tower mast, antennas, and cables are thin structures that are harder to render well.

\subsection*{B2. Objectives and Research Content}
\begin{itemize}[leftmargin=1.2em]
\item Study the original 3DGS pipeline and its training/density-control bottlenecks as the
baseline.
\item Survey multiple published techniques for faster training and better densification, and
verify each one against its own source code. We will focus on techniques that improve rendering
of thin structures (the tower mast, antennas, cables), such as anti-aliasing, opacity/depth
regularization, and density control for sparse regions.
\item Select and combine the most effective techniques into one optimized pipeline for BTS
digital-twin reconstruction.
\item Benchmark the combined pipeline against vanilla 3DGS using PSNR, SSIM, LPIPS, Gaussian
count, training time, and memory use.
\end{itemize}

\subsection*{B3. Expected Results}
\begin{itemize}[leftmargin=1.2em]
\item A short, verified report and slides comparing multiple 3DGS optimization techniques.
\item An optimized 3DGS pipeline for BTS digital twins, combining the best-performing techniques.
\item A real benchmark table comparing the optimized pipeline with vanilla 3DGS.
\end{itemize}

\subsection*{B4. Why this project is suitable for a Computer Graphics course project}
\begin{itemize}[leftmargin=1.2em]
\item \textbf{T1 - Transformations/Hierarchy (Yes - Extensive):} Each Gaussian point in 3D space is defined by geometric transformations: Position (Translation), Rotation (often using Quaternions), and Scale. Additionally, to rapidly render millions of points, 3DGS employs spatial sorting/hierarchical structures (such as depth-based Radix Sort) instead of traditional Hierarchy structures.
\item \textbf{T2 - Camera/Projection (Yes - Core):} The term ``Splatting'' refers exactly to this process. 3DGS uses Camera matrices (View \& Projection matrices) to project these 3D Gaussians onto the 2D screen plane, then rasterizes them into pixels based on the viewing angle.
\item \textbf{T4 - Lighting/Shadows (Indirect / Baked):} The original 3DGS does not compute dynamic lighting or shadows. Lighting, shadow, and reflection effects (view-dependent specular) are all ``baked'' into the Spherical Harmonics parameters during the training process. The scene's luminance changes as you shift your viewing angle, but no actual light source is dynamically created.
\item \textbf{T6 - Interaction/GUI (Yes):} The biggest advantage of 3DGS is its real-time rendering speed (extremely high FPS). This enables the creation of GUIs/Viewers that allow users to interact directly with the scene (rotate, zoom, and pan the camera) with incredible smoothness.
\end{itemize}
